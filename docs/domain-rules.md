# Domain Rules

## Repository Intent
- Primary use: Git practice and lightweight PHP demo.
- Secondary use: Harness Engineering documentation examples.

## Content Rules
- Keep runnable code minimal and beginner-friendly.
- Keep docs practical: short, actionable, and tied to repository reality.
- Avoid speculative architecture that is not implemented.

## Change Rules
- Do not introduce toolchains that hide learning value.
- Prefer additive edits over broad rewrites.
- Preserve existing user-authored content unless explicitly asked to replace it.
